# 거울빛 (MIRRORLIGHT) v2

명세서 v1.1(`mirrorlight-spec.md`)의 「열쇠 릴레이」(1장)에, 두 번째 거울과
시대 정렬 추리를 더한 「크랭크와 관리인」(2장)을 얹은 확장 구현.
정적 페이지, 서버 없음, Three.js r160 (CDN import map).

> 한 문장 요약: **과거는 거울 빛이 닿는 곳에만 존재한다 — 그리고 과거는 하나가 아니다.**

## 실행

```bash
python3 -m http.server 8080
# 브라우저에서 http://localhost:8080 (three.js CDN 로드에 네트워크 필요)
# SSH 접속 중이면: ssh -L 8080:localhost:8080 <host> 후 로컬 브라우저에서 접속
```

기본 진입점(`index.html`)은 2막 《쌍거울의 무덤》이고, 1막 「크랭크와 관리인」은
`chapter1.html`에 있다. `main`에 푸시하면 GitHub Actions가 GitHub Pages로 자동
배포한다 (`.github/workflows/pages.yml`).

- 조작: WASD 이동 · 마우스 시점 · `E` 상호작용 · `G` 놓기(분신) · `F` 빙의/복귀
- 거울 A: `E` 홀드 + 마우스 좌우 = 레일 끌기, 휠 = 회전, `B` 자세 기억, `1/2/3` 호출
- 복귀는 원뿔 안 어디서나 `F` (v2 설계 변경 — 유리까지의 왕복 도보 제거)

## 구조 (v2)

- **시간층 네 개:** `ELDER`(더 이른 때) → `PAST`(10년 전) → `PRESENT` → `RUIN`(멸망 후).
  게임은 두 거울의 선후를 알려 주지 않는다 — 증거가 알려 준다.
- **거울 두 개:** 이동 거울 A는 `PAST`를, 천에 덮여 있던 고정 거울 B는 `ELDER`를 비춘다.
- **관리인(E1→E2 파생 함수):** 부착된 것은 떠날 때 가져가고, 헐겁게 남은 것은
  서랍에 넣어 잠그며, 자기 물건은 제자리로 되돌린다. 수선은 부스러기를 남긴다.
- **정렬의 증거:** 새 못 옆의 오래된 못 자국(수선의 층서), 아궁이의 회반죽 부스러기,
  사라진 놋쇠 문고리의 윤곽, 같은 화분의 묘목과 다 자란 나무.

## 2장의 전략 (검증으로 강제)

1. 크랭크는 E1의 문에서 **뽑아야만** 살아남는다 (부착된 채면 관리인이 가져간다).
2. 헐겁게 남긴 크랭크는 어디에 두든 **잠긴 E2 서랍**으로 깔때기처럼 모인다.
3. 서랍은 E2의 마루장 밑 여벌 열쇠로만 열린다 (수선된 못 자국이 위치를 밀고한다).
4. 빗장 해제는 두 경로다. **경로 B(우아한 길):** E2의 빗장 축에 크랭크를 끼우고
   돌려 둔다 — 물체는 이후 약탈되어 축에 윤곽만 남지만, **빗장의 상태는 인과를
   타고 현재로 흐른다** (서랍 자물쇠·마루장 못과 같은 문법). **경로 A:** 크랭크를
   벽돌로 현재에 배달해 현재의 축에 끼운다. 두 경로 모두 유효하다.
5. 어느 경로든, 현재에서 녹슨 열쇠로 자물쇠를 열면 문이 열린다.

배달의 법은 그대로다: **물체**는 은닉처로만 시간을 건너지만, 고정물의 **상태**
(자물쇠·못·빗장)는 언제나 하류로 파생된다 — 경로 B는 새 규칙이 아니라 기존
규칙의 정직한 적용이다.

## 검증 (`node src/validate.js`)

- **1장 기하:** 조건 0(치팅 자세) 위반 0건, 미포함 보행 셀 0개.
- **2장 기하:** B 고정 자세의 상호작용 지점 전부에 여유 0.15m 이상, 벽난로 제외,
  스폰 성립. E2에서 서랍∧벽돌 동시 자세 0건, 마루장∧서랍 동시 자세 4,294건,
  서랍∧빗장 소켓 동시 자세 1,429건(경로 B 성립), 릴레이 공유 셀 197개.
- **모델 검사:** 관리인 규칙과 빗장 상태를 포함한 상태 그래프 2,139개 상태 전수
  탐색 — 모든 도달 상태에서 승리 도달 가능(소프트락 0). 이 검사가 실제로 잡아낸
  함정: 서랍을 열기 전에 작은 열쇠를 벽돌로 회수하면 시간선이 끊긴다 →
  「돌려놓기」 동사로 복원.

## 명세에서 벗어난 결정 (기록)

- **인위적 차단 없음.** 옛 거울의 천은 처음부터 걷을 수 있고, 문의 두 잠금
  (자물쇠·빗장)은 어느 순서로 풀어도 된다. E1의 문 열쇠도 자유롭게 만질 수 있다
  — 어디에 두든 관리인이 걸이로 되돌리므로(R6) 시도 자체가 규칙을 가르친다.
  경로는 강제가 아니라 발견이다. 모델 검사가 1,091개 도달 상태 전부에서 승리
  가능함을 증명한다.
- 6.4절의 복귀 근접 조건(거울 1.5m)을 제거했다. 경계 학습이 끝난 뒤에는 결정이
  없는 도보만 남기 때문이다. 같은 이유로 거울 자세 북마크를 추가했다.
- 7.2-8("회수 후 빙의 비활성화")은 6.7절과 충돌하므로 6.7절을 따랐다.

차별점: 위 선례들은 투사·포털·순방향 인과를 따로 쓴다. 《거울빛》 v2의 고유성은
결합에 있다 — 빛이 닿는 곳만 과거가 존재하고, 물건은 시간이 배달하며, 미래가
답안지로 먼저 대답하고, **시간선의 순서 자체가 숨겨진 퍼즐이다: 낡음이 아니라
수선의 흔적이 시간의 화살표다.**

## 두 번째 무대: 《쌍거울의 무덤》 (`index.html`, 기본 진입점)

같은 규칙, 다른 무덤. 두 방(전실·매장실)이 가운데 돌벽으로 나뉘고, 청동 거울
두 개가 각 방의 끝에서 서로를 마주 본다 — 회전만 가능하다. 거울 A는 도굴의 밤
(파공이 뚫린 봉인 석판)을, 거울 B는 봉인의 날(열린 통로, 사제단)을 비춘다.
플레이어는 현대의 도굴꾼이다: 크립트는 이미 뜯겨 비어 있다 — 옛 도굴꾼들이
먼저였다. 이기는 길은 그들보다 이르고 그들보다 늦는 것뿐이다.

- **개구 차폐(신규 규칙 확장):** 빛은 벽을 건너지 못하고 시대별 개구(열린 문 /
  도굴꾼의 파공)를 통해서만 옆방에 닿는다. 파공은 바늘구멍이 되어 거울 A의
  원뿔을 쐐기로 깎는다 (`conemath.throughAperture`).
- **사제단 = 관리인의 유비:** 흐트러진 부장품은 정위치로, 도구는 벽감으로.
  봉인의 날의 편집은 전부 흡수된다 — 경문이 그 규칙을 처음부터 알려 준다.
- **도굴 = 약탈 구간의 유비:** 보이는 것·값진 것은 전부 사라진다. 유일한 생존
  은닉처는 도굴꾼들 발밑의 밋밋한 들뜬 바닥돌 — 현재에 홀로 온전한 것이 답이다.
- **시간 충돌 회피:** 시대 씬 속 거울들은 천 덮인 소품(재귀 금지); 크립트를
  일찍 열면 현재의 증거가 정합하게 바뀐다(뜯은 자국 소멸); 선-은닉은 규칙(사제단
  흡수)과 기하(B 원뿔이 바닥돌에 닿지 않음, 검증 Q7=0)로 이중 봉쇄된다.
- **검증:** `node src/pyramid/validate.js` — 크립트∧바닥돌 동시 자세 0(릴레이
  강제), 릴레이 공유 셀 151, 쐐기 밖 지점 개구 차단 증명, 모델 검사 23개 상태
  전수 소프트락 0.
